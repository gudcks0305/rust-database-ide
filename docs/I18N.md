# Korean and English application messages

`dbide-i18n` provides an offline, lightweight typed catalog for core application
captions and status/error wrappers. It depends only on `serde` at runtime. There
is no network lookup, user-file discovery, translation service, locale download
or global process mutation. The application owns persistence and redraw.

## Stable API

```rust
use dbide_i18n::{Locale, Localizer, Message, tr};

let mut ui = Localizer::default(); // Korean
assert_eq!(ui.text(Message::Preferences), "환경설정");
ui.set_locale(Locale::En);
assert_eq!(ui.text(Message::Preferences), "Preferences");
assert_eq!(tr(Locale::Ko, Message::Run), "실행");
assert_eq!(
    ui.format(Message::SelectedDatabase, &[("database", "Sales_한국어")]).unwrap(),
    "Working database: Sales_한국어"
);
```

- `Locale::{Ko, En}` serializes/deserializes exactly `"ko"` / `"en"`. `Ko` is
  the default. Unsupported values are rejected; the preference owner decides
  how to report or recover invalid stored settings. `Locale::code()` returns
  the matching code and `Locale::ALL` enumerates supported languages.
- `Localizer::new(locale)`, `.locale()`, `.set_locale(locale)`, `.text(message)`
  and `.format(message, arguments)` support runtime switching without rebuilding
  the catalog. Global `tr(locale, message)` and `format(locale, message, args)`
  are also available. Plain lookup returns `&'static str` without allocation.
- `Message` is an exhaustive enum. `Message::ALL` covers the catalog;
  `.id()` / `Message::from_id()` support introspection with exact variant names
  and return `None` for unknown ids rather than silently displaying a key.
- All message variants and both translations are defined together in one
  `catalog!` invocation in `crates/dbide-i18n/src/lib.rs`. Adding a message
  requires both Korean and English text in the same row. Enum lookup cannot
  miss a locale at runtime.

The catalog covers core menu/buttons, preferences/language names, connection
forms/actions, explorer/object categories, connection/database selectors,
per-console database captions, session/transaction/cancel states, dirty-document
and recovery prompts, query/results labels, and error wrappers. It is a
foundation for host integration, not a claim that every existing UI surface or
experimental feature is already translated. Korean and English entries for the
language selector intentionally use each language's native name in both locales.

## Bounded interpolation and data preservation

Templates use named placeholders such as `{error}`, `{name}`, `{count}` and
`{database}`. `format` validates the exact expected argument set, rejecting
missing/unknown/duplicate names and malformed template syntax. Limits:

| Resource | Bound |
| --- | --- |
| Arguments per call | 16 |
| Each argument value | 4,096 UTF-8 bytes |
| Argument name | 1–64 ASCII lowercase letters/underscores |
| Formatted result | 64 KiB UTF-8 |

Arguments are inserted verbatim once; braces inside a value are not recursively
interpreted. This is text formatting, not SQL or HTML escaping. Never translate,
case-fold, rename or otherwise rewrite SQL source, schema/table/column/database
identifiers, connection/profile names, raw database diagnostics, SQLSTATE codes
or user-entered values. Translate only the application-owned wrapper. Tests
verify preservation of mixed-case names, Korean identifiers, SQL text and raw
server messages containing braces. Oversized values return an explicit error,
not a truncated identifier or diagnostic. A host showing a larger diagnostic
can render a translated static `ErrorDetails` label beside its independently
bounded raw-error view.

Human review remains necessary for translation quality and context-specific
wording. This catalog does not implement automatic plural rules, locale-specific
numeric/date formatting or machine translation.

## GPUI component locale boundary

The installed dependency `gpui-component = 0.8.0` was inspected locally:

- `src/lib.rs:125` declares `rust_i18n::i18n!("locales", fallback = "en")`.
- `src/lib.rs:154` exposes `gpui_component::locale()`.
- `src/lib.rs:159` exposes `gpui_component::set_locale(locale: &str)`.
- Bundled `locales/ui.yml` contains no `ko:` translation entries.

The host can call `gpui_component::set_locale(locale.code())` when changing its
own locale. Setting `"ko"` alone does **not** add Korean built-in translations:
missing component messages fall back to English. Core application captions
must use the typed application catalog. Any later upstream component override
or bundled Korean component dictionary requires its own verified integration;
no dependency source is modified by this crate.

## Verification

```sh
cargo test -p dbide-i18n
cargo clippy -p dbide-i18n --all-targets -- -D warnings
cargo fmt -p dbide-i18n -- --check
```

Tests cover complete/nonempty catalogs, unique/round-trip keys, placeholder
parity across languages, successful formatting of every message in both locales,
exact locale JSON values/default/runtime switching, malformed templates,
missing/unknown/duplicate arguments, byte/count/output limits, and verbatim SQL,
identifier and raw-error preservation. They do not exercise native UI redraw,
preference persistence or built-in component translations; those belong to host
integration and native QA.
